# Catch-up experience review — 2026-09-24

The acceptance target is a fast, attractive newspaper that groups related coverage, supports deeper summaries and article/library questions, and lets chat find relevant articles. This review does not claim that the full target or shared-core migration is complete.

## Changes verified in this slice

- Today fills the available desktop space until a reference is opened, then becomes a compact reading column. Larger newspaper layouts use aligned columns; narrow layouts keep a single readable column. Translucent surfaces and the existing native window material remain in place.
- Each story appears once. All reports, including syndicated copies, stay available behind an explicit disclosure. Headlines are keyboard-operable buttons, controls share dimensions, and read stories retain legible contrast.
- Empty editions can fill after feed refresh. Populated editions remain immutable. Previously consumed stories do not return merely because another syndicated copy arrived; a new material revision can bring them back.
- Fresh native databases receive the lede column. The migration previously attempted to alter the table before creating it.
- Library chat searches the complete selected scope before limiting results, including URLs and cached reader bodies. Word boundaries prevent “AI” from matching “daily.” Specific unmatched questions receive an honest no-match result; broad catch-up requests can still use recent coverage.
- Detailed summary word counts reach the provider settings and cache key. Late lede events and read-save results remain scoped to their originating edition. Failed saves and load errors are visible and retryable.
- Follow-ups such as “summarize that” retain the last user topic and referenced articles after opening a source marks it read. Opening and closing a cited article returns to the preserved Ask conversation. Article questions receive the visible generated summary as bounded, untrusted context, with the original article as evidence.
- Meaningful headline clauses are retained, reordered proper nouns can corroborate the same event, and syndicated copies no longer remove single-source ranking protection. Version-2 derived features refresh lazily from raw articles; existing story memberships, revisions and frozen editions remain unchanged.
- Desktop and iOS now execute one `shared/SkimStoryPolicy` implementation for confidence, classification thresholds/decisions, base ranking, unique-source protection and the stable identity hash. Feature extraction, selection, preferences and persistence remain separate.

## Shared semantic edition path

Both products now call the shared C prompt, numeric validation and importance adjustment before freezing a new edition. Only the configured provider is used, outside database locks, with one 30-second deadline covering both inference passes. The complete eligible pool must contain at most 64 stories; larger pools retain deterministic selection. Foundation Models has a conservative input/output budget; no partial candidate pool or cloud fallback is substituted. Proposed merges require a second comparison of every member pair, capped at 64 pairs. Both apps use the shared C prompt and deterministic complete-clique partition: positive A–B and B–C links alone cannot merge A with C. Missing, duplicate, foreign or malformed pair identities discard the semantic plan; uncertain pairs remain separate. Whole JSON objects or arrays, optionally fenced, are accepted with explicit `members` or `pair` identities; positional guesses are never used. Pair dates are labeled `activity_date` because they derive from story activity, not necessarily publication.

Valid groups retain all source references and each constituent story revision. Consumption suppresses every constituent until material news changes it. Existing populated editions stay frozen; stale revisions or source membership changes during inference discard the plan. Migrations backfill old items as singleton groups. Invalid, overlapping, out-of-range and low-confidence groups cannot remove candidates; omitted candidates remain singletons. Shared fixture tests cross the Swift and Rust ABI adapters.

Earlier Gemma 1B and Qwen 1.7B probes used a stale September 13 helper (SHA-256 `8b3705c2202bbd06c6c2c875b420b1af687cd0b5e7b7725cc5abb2cb0c3f2d4f`). The release script selected that binary from a previous SwiftPM directory layout even after a successful compile. Those observations remain failure/rejection evidence, **not current-source inference evidence**. The recorded malformed response in `shared/fixtures/semantic-model-failure.json` retains that provenance.

## Shared inference policy and packaging fixes

Native iOS, the desktop helper and the legacy Tauri iOS adapter now consume `shared/SkimInferencePolicy` for model-family detection, turn terminators, thinking-template flags, sampling presets and answer cleanup. Desktop preserves caller temperature, including the semantic planner's zero. Cleanup removes leading reasoning and trailing turn markers while retaining literal tokens, HTML and generic types inside answers.

Bridge packaging now asks SwiftPM for the exact output directory using the same build arguments. Three hermetic regressions cover coexisting stale/current products, missing executable and missing resources; all failed against the old script and pass with the fix. A second actual-runtime finding showed the desktop-recommended Qwen 4B model missing its standalone chat template after download; the library silently converted messages to plain text. Shared cache validation and matching template downloads now prevent this degraded fallback and allow repair without deleting weights. An actual cache repair changed readiness from false to true, completed in 1.06 seconds, and preserved every weight-file SHA-256. Leading reasoning, literal token preservation, embedded/standalone template formats, malformed config and precedence are covered by the 13 policy tests.

The shared semantic prompt no longer includes example member indexes or example scores. With the corrected helper, Qwen 1.7B grouped all eight original synthetic reports correctly and ranked major consequences above minor changes. However, both the old and new prompts failed the ten-report public-news sample in `shared/fixtures/semantic-real-news.json`: valid JSON still merged distinct decisions or products. Gemma 1B also failed. With its template repaired, Qwen 4B passed all broad importance constraints but still over-grouped distinct dates, authorities and products. The corpus uses dated 2023–2024 reports and researcher paraphrases, with labels excluded from input and equal base scores; it is a small historical editorial test, not live-feed acceptance or proof of general accuracy. Apple Foundation Models remains unavailable because Apple Intelligence is disabled on this host. No app provider settings were changed; public fixtures ran locally. The supported Qwen 1.7B and desktop-recommended Qwen 4B models were downloaded to the local cache for these probes.

The bounded verification pass was then tested against that ten-report development corpus and a fresh eight-report corpus on different topics (`semantic-fresh-news.json`). The final Qwen 4B pipeline matched all twelve expected story groups across eighteen reports and all broad importance constraints, in 5.94 and 5.39 seconds respectively. Raw real responses in `semantic-verification-responses.json` replay through both production adapters. One pair judgment in the fresh sample was wrong; the all-pairs clique rule kept those events separate in this case. This is limited, hand-selected historical evidence, not a guarantee of factual judgments, unseen training data, personalization, or current-feed quality. The verifier cannot recover same-event pairs omitted by the first pass. Split groups inherit the first-pass importance rating, which may misrate an individual fragment; their original factual explanation is replaced with neutral copy. Gemma 1B and Qwen 1.7B still do not pass the complete semantic protocol.

Native calls now preserve per-request temperature overrides through configured-provider adapters without saving settings. Both semantic calls use zero; Apple Foundation Models uses greedy sampling for zero. Actual Foundation Models inference remains unavailable on this host.

## Remaining acceptance

`skim-do2h` tracks semantic grouping and importance on real feed coverage: low-overlap paraphrases, similar topics that are separate events, and important single-source stories. The bounded semantic path is now wired in both apps, but the cached 1B model failed the isolated quality check. The two Qwen 4B historical samples now pass the bounded two-stage pipeline. Current-feed grouping/importance, reliable small-model output, independently rated split fragments, and candidate pools larger than 64 remain unaccepted. Numeric validation cannot establish whether a structurally valid model grouping is editorially correct.

`skim-dz1g` remains open for installed-app hands-on acceptance and live-provider quality. Initial installed-app exploration stopped at Terms acceptance; the current attempt to reconnect to the native app timed out. No acceptance was inferred or clicked.

`skim-62qe` tracks sharing the full desktop/iOS domain implementation. The bounded policy extraction is `skim-62qe.1`; Rust desktop and Swift iOS still own separate feature extraction, selection and stores. Matching fixes outside the extracted policy are parity evidence, not shared implementation.
